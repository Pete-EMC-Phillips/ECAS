This POC

Runs entirely client-side against mock data — no JIRA, no Tableau. Demonstrates the target data model (programme → vehicle line → component → GRADE / EMC / FUSA / Cyber record, plus component-level R&R plans and deviations) and the KPI views this would replace, in one shareable file. Today it is one ticket per GRADE review and one per EMC review, ~40,000 JIRA tickets in total; the target model is one component record, linked to every vehicle line it's fitted to, with every review area tracked directly against it.

Planned extensions
1
Real data store, not JIRA
Move the repository off JIRA before its March 2029 retirement, onto a proper database with an import path for existing vehicle line and ticket data.
2
Bill of materials linkage
Trace BOM entries — starting with semiconductors — into the hardware part number and module tracking, so a component's dependencies are visible, not just its own sign-off.
3
Radio type approval
Track type-approval status for components containing transmitters.
4
Functional safety & cyber security — define the real workflow
FUSA and Cyber tracking now exist as placeholders copied from the GRADE headings; replace with the real classification and evidence workflow once defined.
5
Software levels at sign-off
Record the software version used at vehicle sign-off for each component.
6
ECE Reg 10 & Reg 155 evidence
Once component, software and BOM data are all under one roof, use it as the evidence base for vehicle-level ECE R10 (EMC) and R155 (cyber security) sign-off.
